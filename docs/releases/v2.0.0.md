# VastraAI v2.0.0 — release preparation

**Status:** Versioned release candidate. Not committed, tagged, or published. Release gates remain open; this document does not claim production readiness.

## Highlights

- Keeps the v0.2 SearchState, session, refinement, hybrid retrieval, exact-filter, and product-first UI architecture.
- Adds bounded catalog context and concise grounded answers for product comparison and product-context questions. Structured claims and product references are validated against retrieved catalog data before the server renders an answer.
- Records retrieval/RAG latency, context size, provider/model, grounding failures, and invalid-reference failures in existing request-correlated observability.
- Extends evaluation with semantic, hybrid, hybrid-plus-grounding modes and deterministic adversarial grounding checks.
- Fixes conversational category switches such as “black dress” → “shoe under 3000”, prevents stale filter words from vetoing refined searches, supports broad blue/green/purple catalog color families, and keeps the chat input synchronized with React state.

## Evaluation evidence and limits

The 40-query evaluation was run on the pinned 750-product synthetic catalog before the last query-normalization and color-family fixes. It must be rerun against the final release candidate before release claims are made.

| Retrieval mode | Precision@5 | Recall@10 | MRR | NDCG@10 | Hard-filter violations |
| --- | ---: | ---: | ---: | ---: | ---: |
| Offline keyword | 84.4% | 81.6% | 95.8% | 94.8% | 0 / 258 |
| Semantic only | 0% | 0% | 0% | 0% | No results |
| Hybrid | 84.4% | 81.6% | 95.8% | 94.8% | 0 / 258 |
| Hybrid + grounding harness | 84.4% | 81.6% | 95.8% | 94.8% | 0 / 258 |

The evaluation database had no ready compatible embedding index. Semantic-only therefore returned no products, and hybrid used its existing FTS fallback. Hybrid-plus-grounding is post-retrieval; unchanged retrieval metrics are expected. The grounding suite is deterministic and adversarial, not a live model-quality benchmark: it rejected proposals with missing or incorrect facts and an unknown product reference; emitted invalid references and unsupported claims were both zero across the four fixtures. No live RAG generation latency or API cost was measured.

The earlier offline-keyword baseline scored P@5 80.0%, Recall@10 80.1%, MRR 94.4%, NDCG@10 94.1%, and zero hard-filter violations. Those before/after values are from separate offline runs and predate the final v2 query fixes; rerun the pinned evaluation before publishing a v2 comparison.

## Manual local checks

After the latest search fixes, direct calls through the local backend search/state code returned five results for each of:

- `black dress under 4000`
- Start from that state, then `shoe under 3000` (state resets to footwear and preserves the same session flow)
- Change the original dress search to `make it blue` (returns navy-blue and powder-blue products under the blue family filter)

These are backend/catalog checks, not a full browser acceptance run. The production Docker build completed and local frontend/backend health endpoints returned HTTP 200. Automated tests have not been rerun after the final search-normalization fixes.

## Release gates still open

- Rerun backend and frontend suites against the final v2 source, then rerun the pinned retrieval and grounding evaluation.
- Exercise the full conversation in desktop and mobile browsers, including submit/clear behavior, category switch, filter removal, product/back navigation, and refresh restoration.
- Refresh desktop/mobile screenshots; current README screenshots predate the redesign.
- Record a live-provider RAG latency/cost run only with explicit provider credentials and cost review; deterministic evaluation does not supply those figures.
- Verify remote CI and review the known development-only npm audit findings before publication.
- Confirm deployment uses a single backend worker or replace the process-local search session store with shared persistence before horizontal scaling.
