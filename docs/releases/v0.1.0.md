# VastraAI v0.1.0 — release candidate notes

Status: **candidate, not tagged or published until every release gate passes**.

## Highlights

- Deterministic 750-product synthetic catalog; natural-language search with exact fashion filters, keyword/compatible semantic retrieval, RRF fusion, grounded explanations, and keyword degradation.
- Delta-based conversational refinements with revision conflicts and browser same-tab view restoration while the backend session remains alive.
- Gemini/Ollama provider interfaces; request-correlated provider/search observability and a development-only dashboard.
- Human-labelled 40-query offline keyword evaluation with pinned catalog checksum and comparison tooling.

## Stabilization in this candidate

- Footwear sizes such as 9 now parse from the existing size taxonomy.
- Category aliases are normalized for retrieval instead of leaving unmatched synonym terms.
- Fresh-database FTS trigger fixed; migration, seed, and evaluation verified on an untouched local database.
- Next.js production build now includes Tailwind through PostCSS and uses the verified webpack builder; browser search view persists in the same tab and result links use Next navigation.
- GitHub Actions checks backend lint/tests/migrations/evaluation, frontend lint/types/tests/build, and container builds without live AI-provider secrets.

## Measured evaluation

On the unchanged v1 dataset, filter exact match rose from 97.5% to 100%, Precision@5 from 80.0% to 84.44%, Recall@10 from 80.07% to 81.60%, and NDCG@10 from 94.09% to 94.76%. Hard-filter violations remained zero. These are **offline keyword** results, not evidence of live hybrid improvement. Full values and failure classifications: [comparison](../evaluation-release-comparison.md).

## Known limitations and next steps

The seed has no wedding dresses, so the requested black-wedding-dress product smoke cannot pass as written. Sessions are process-local; restarts and multiple workers invalidate them. A fresh seed requires an explicit embedding pass for semantic retrieval. The evaluation set is small and lacks a live semantic benchmark. The developer dashboard has no admin auth and must remain local. Next: expand catalog/evaluation coverage, persist sessions with atomic revisions, then add a separate live-hybrid quality gate.
